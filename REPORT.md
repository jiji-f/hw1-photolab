| Что | Значение |
|---|---|
| поворот 30°: размер до → после, пустой холст | 960 × 1280 → 1472 × 1589; 47.5 % |

| то же на iu-building.jpg | 27.9 / 35.9 / 37.2 дБ |
| выпрямление: стороны в кадре | верх 644.9; право 749.0; низ 761.1; лево 1078.6 px |
| aspect; размер выхода | 0.707; 761 × 1076 |
| poster-angle.jpg курса: совпадение с poster-gt.png | 99.10 % при размере 640 × 905, бинаризация серого по порогу 128 |

Формула холста: 960·cos(30°) + 1280·sin(30°) ≈ 1471.4; 960·sin(30°) + 1280·cos(30°) ≈ 1588.5. Округление вверх даёт 1472 × 1589. Пустой холст вычислен по площадям, не по числу белых пикселей.

Для обложки 0.707 использовано как приближение вертикального формата A4. Реальная пропорция книги не измерена, поэтому возможны искажения пропорций. При уменьшении страницы тонкие штрихи букв и мелкий текст становятся менее различимыми. На своём снимке blur ближе к Lanczos по PSNR, на здании ИУ лучше area. На здании результат blur отличается от примера курса (36.0) на 0.1 дБ; в нашей реализации размытие выполняется во float32 перед окончательным округлением.

## 2. Три вопроса

**2.1. Какое цветовое пространство выбрано для хромакея и почему? Что было бы в RGB?**

Я выбрала HSV: H задаёт оттенок, S — насыщенность, V — яркость. Для коробки H = 5…25 и S ≥ 170 отделяют насыщенный оранжевый цвет, V ≥ 150 исключает тёмные участки, но теряет боковые грани. В RGB изменение освещения меняет сразу несколько каналов, поэтому прямоугольные границы труднее подобрать. Белый рисунок не проходит оранжевые границы HSV, поэтому отдельный скрипт заполняет внутреннюю область выбранного контура; итоговая маска занимает 6.57 % кадра.

**2.2. Что происходит с гистограммой при γ < 1 и при γ > 1? Куда деваются обрезанные пиксели?**

При γ = 0.5 тёмные ненулевые значения увеличиваются: среднее выросло с 13.7 до 48.9, медиана с 9 до 45. При γ = 2 значения уменьшаются: среднее стало 1.9, доля чёрных выросла до 51.71 % из-за округления малых значений в ноль. Значения 0 и 255 отдельных каналов остаются на границах: потерянные при съёмке детали не восстанавливаются, а округление может сливать значения или создавать пустые столбцы гистограммы. Доли крайних значений в отчёте считаются после перевода результата в серый, поэтому могут меняться даже при сохранении крайних значений отдельных цветовых каналов.

**2.3. Почему CLAHE лучше equalizeHist на вашем фото — по числам?**

Глобальная эквализация увеличила σ в тенях с 0.4 до 21.2, среднее в светах с 31.0 до 232.0; визуально появились сильные пятна и ступенчатые переходы. CLAHE повысил σ до 1.9 и среднее в светах до 46.6, то есть изменение было мягче. CLAHE лучше сохраняет плавные переходы, но кадр остаётся тёмным; большее σ само по себе не доказывает полезный контраст, поскольку включает шум. Для заметного осветления здесь эффективнее γ = 0.5, которая также усиливает видимость цветного шума.

## 3. Где сломалось

Попытка выделить розовый флакон: `chromakey data/object.jpeg --bg data/bg.jpeg --lo 155,85,40 --hi 179,255,255 --close 15`. Маска потеряла некоторые тёмные области и захватила красный фрагмент соседней упаковки. Причины — похожие оттенки соседних предметов, неоднородная яркость и соединение областей при закрытии. Итоговый пример использует оранжевую коробку, более строгие границы, выбор контура по точке и заполнение внутренних отверстий; прежняя команда его не повторяет.

Окно выбора углов сначала не помещало вертикальное фото по высоте. Я разрешила изменить функцию преподавателя `pick_corners`: добавлено ограничение высоты с учётом экрана, координаты кликов пересчитываются в исходный размер. Сначала я выбрала только два угла и получила ожидаемую ошибку; затем выбрала четыре угла, и запуск прошёл успешно.

## 4. Команды

Выполнять из корня репозитория. Команды воспроизводят все текущие файлы в `out/`.

```powershell
python photolab.py gamma data/dark.jpeg --gamma 0.5 -o out/dark_g05.jpg --hist out/dark_g05_hist.png
python photolab.py gamma data/dark.jpeg --gamma 2 -o out/dark_g2.jpg --hist out/dark_g2_hist.png
python photolab.py gamma data/bright.jpeg --gamma 2 -o out/bright_g2.jpg --hist out/bright_g2_hist.png
python photolab.py wb data/bright.jpeg --method grey-world -o out/bright_gw.jpg
python photolab.py wb data/bright.jpeg --method white-patch -o out/bright_wp.jpg
python photolab.py clahe data/dark.jpeg --clip 2 --tiles 8 -o out/dark_clahe.jpg --compare out/dark_cmp.jpg --hist out/dark_clahe_hist.png
python photolab.py rotate data/poster.jpeg --deg 30 -o out/poster_rot30.jpg
python photolab.py resize data/text.jpeg --scale 0.25 --report -o out/text_x025.jpg
python photolab.py rectify data/poster.jpeg --corners 226.74285888671875,137.14285278320312,833.8285522460938,354.74285888671875,874.05712890625,1102.6285400390625,120.68571472167969,1210.5142822265625 --aspect 0.707 -o out/poster_front.jpg
python orange_object.py
python photolab.py sheet data/object.jpeg out/object_on_bg.jpg out/object_mask.png out/poster_front.jpg --cols 2 -o out/sheet.jpg
python check_samples.py
python -m pytest tests -q
```

`check_samples.py` печатает метрики кадров курса, не изменяя `out/`. Он ищет папку `lectures` в корне репозитория курса автоматически; в отдельной копии работы эти кадры должны быть доступны. `orange_object.py` работает с файлами относительно собственного расположения.
